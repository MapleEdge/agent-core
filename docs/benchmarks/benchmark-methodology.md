# Benchmark Methodology

## Honest Classification

The benchmarks in this repository are classified into two tiers:

### Tier 1: Pipeline Validation (Currently Implemented)

These tests verify that the **memory capability pipeline** (ingest → search → retrieve → generate answer → evaluate) functions correctly. They use:

- **Synthetic golden fixtures**: 20–30 hand-written questions per benchmark with 4–5 context entries each
- **MockMemoryProvider**: SQLite FTS5, no vector embeddings
- **Mock LLM** (`BenchmarkLLMClient`): Deterministic answer generation from retrieved evidence
- **Small datasets**: Each question ingests only its own context entries (≤5 per question)

**What they prove:**
- The capability pipeline executes without errors
- FTS retrieval finds relevant context entries
- Answer generation produces structured output
- Abstention triggers correctly on empty gold answers
- Correctness evaluation (Jaccard, containment, key-term matching) works

**What they do NOT prove:**
- Memory quality at scale (1K, 1M, 10M memories)
- Semantic retrieval quality (no embeddings used)
- Real LLM answer generation quality
- Parity with external benchmark datasets (LoCoMo, LongMemEval, BEAM papers)
- Retrieval under noise/distractor conditions

### Tier 2: Scale Parity (Partially Implemented)

These tests measure retrieval **degradation under scale**:

- `scale-retrieval.test.ts`: Loads 1000+ distractor memories alongside target memories, measures Recall@1/3/5 as corpus size grows
- Uses the same MockMemoryProvider (FTS5) to establish a **baseline** that future providers (mem0, hybrid) must beat

**What they prove:**
- FTS recall degrades predictably as corpus grows
- The provider contract handles large datasets without crashes or data loss

### Tier 3: External Benchmark Parity (NOT YET IMPLEMENTED)

True parity with published benchmarks requires:

| Requirement | Status |
|---|---|
| Real LoCoMo dataset (ACL 2024) | Not loaded — synthetic fixture approximation only |
| Real LongMemEval dataset (ICLR 2025) | Not loaded |
| Real BEAM dataset | Not loaded |
| Real LLM (DeepSeek/GPT-4) for answer generation | Mock only |
| Real embedding model for semantic retrieval | Mock only |
| 1M+ memory corpus for BEAM-1M | Not implemented |
| 10M+ memory corpus for BEAM-10M | Not implemented |

## Naming Conventions

| Test file | What it actually tests |
|---|---|
| `locomo.test.ts` | Pipeline validation using LoCoMo-shaped fixtures (27 questions) |
| `longmemeval.test.ts` | Pipeline validation using LongMemEval-shaped fixtures (20 questions) |
| `beam.test.ts` | Pipeline validation using BEAM-shaped fixtures (10+8 questions) |
| `scale-retrieval.test.ts` | FTS recall degradation at 100/500/1000 memory scale |

## Mock LLM Behavior

`BenchmarkLLMClient` is deterministic:

1. If evidence is found AND gold answer is available → returns gold answer (tests retrieval + evaluation pipeline)
2. If gold answer is empty → returns abstention (tests abstention detection)
3. If no evidence found → returns abstention

**This means pipeline validation tests are primarily testing retrieval (can FTS find the right context?) and correctness evaluation (does token overlap detect the match?). The LLM step is a passthrough.**

## Correctness Evaluation

`evaluateCorrectness(gold, predicted, abstained)` uses:

1. Exact match (normalized)
2. Containment (predicted includes gold or vice versa for strings >10 chars)
3. Jaccard token overlap ≥ 0.5
4. Key-term matching ≥ 60% of gold answer key terms present in prediction

## Adversarial Fixtures

The adversarial test category verifies that the system **abstains** when:

- Context entries are present but don't answer the question
- The gold answer is empty (signals expected abstention)
- Retrieved evidence is topically related but not responsive

## Scale Test Methodology

`scale-retrieval.test.ts` measures recall degradation:

1. Insert N distractor memories (random domain-relevant sentences)
2. Insert target memories for each question
3. Query each question
4. Measure whether target memories appear in top-K results
5. Report Recall@1, Recall@3, Recall@5 at each scale tier

## How to Run

```bash
# Pipeline validation (CI-gated)
pnpm test

# Scale benchmarks
pnpm test -- tests/benchmarks/scale-retrieval.test.ts

# Full benchmark with JSON output
pnpm bench
```

## Raw Output

Machine-readable benchmark results are generated by `scripts/benchmark-runner.ts` and saved to `docs/benchmarks/raw/`. These include per-question results, timing, and accuracy breakdowns.

## Roadmap to Tier 3

See `docs/benchmarks/long-memory-benchmark-roadmap.md` for the phased plan to reach real external benchmark parity. Prerequisites:

1. Real LLM integration (DeepSeek API)
2. Real embedding model (text-embedding-3-small)
3. mem0 provider as retrieval backend
4. Dataset loaders for LoCoMo, LongMemEval, BEAM
5. Corpus generation tooling for 1M+ memory scale
